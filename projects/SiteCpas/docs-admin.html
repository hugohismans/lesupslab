Documentation Admin

Guide complet pour configurer, déployer et administrer moncompagnon dans une organisation.

📖

À propos de ce guide

Ce document est destiné aux intégrateurs et administrateurs système

Ce guide couvre l'intégralité des paramètres de moncompagnon — de la création d'une organisation aux détails de chaque fonctionnalité, en passant par la structure Firebase et les rôles de chaque poste.

Pour les agents du quotidien — la documentation utilisateur par poste est disponible sur docs.html. Ce guide-ci est réservé à la configuration et à l'administration technique.

🔧 Prérequis techniques

  • Compte Firebase — projet Realtime Database configuré avec les règles de sécurité appropriées
  • Accès superadmin — mot de passe global (distinct des mots de passe des organisations)
  • Navigateur moderne — Chrome ou Firefox à jour (ES2020+ requis)
  • Hébergement statique — GitHub Pages, Netlify, Firebase Hosting ou équivalent
  • config.js complété — ORG_ID, FIREBASE_CONFIG, VAPID_KEY (optionnel, pour push)
🏗️

Configuration initiale

Mettre en place une nouvelle organisation de A à Z

🏢 Créer une organisation (superadmin.html)

Chaque organisation est identifiée par un orgId unique (slug), préfixe de toutes ses données Firebase.

  1. Accéder à superadmin.html Entrez le mot de passe global (distinct des mots de passe des organisations clientes).
  2. Créer l'organisation Renseignez l'orgId (ex: cpas-quaregnon), le nom affiché, la mascotte par défaut et les modules à activer d'emblée.
  3. Générer un token d'onboarding Ce token permet au client de remplir onboarding.html une seule fois pour pré-configurer agents, locaux et services.
  4. Configurer config.js Renseignez ORG_ID, les clés Firebase et optionnellement VAPID_KEY pour les notifications push.
Convention orgId : utilisez un slug kebab-case sans accents ni espaces (cpas-quaregnon, cpas-boussu). Il ne peut pas être modifié après création sans migrer les données.

🔒 Mots de passe & accès

Tous les mots de passe sont stockés côté Firebase sous forme de hash SHA-256. Aucun mot de passe n'est jamais stocké en clair ni dans le code source.

ÉlémentStockage FirebaseDescription
Mot de passe agentorgs/{orgId}/appConfig/agentPasswords/{agentKey}Hash SHA-256 du code personnel. Si absent → connexion libre (sélection du nom suffit). Défini à la première connexion ou réinitialisé par l'admin.
Mot de passe superadminsuperadmin/passwordHashHash SHA-256 — accès à superadmin.html. Créé à la toute première ouverture (écran de création dédié).
Mot de passe documentation adminsuperadmin/docsAdminPasswordHashHash SHA-256 — protège docs-admin.html. Configuré depuis superadmin.html. Si absent → accès libre.
  • Réinitialiser un code agent : Paramètres → Agents → bouton Réinitialiser → supprime le hash, connexion redevient libre
  • Modifier son propre code : page de connexion → "Changer mon code"
  • Superadmin : si le hash est supprimé manuellement de Firebase, la page repasse en mode création au prochain chargement

🔄 Administrateur temporaire

Lorsqu'un administrateur doit s'absenter, il peut déléguer ses droits à un collègue le temps de son absence.

1
Déclencheur L'admin clique "Au revoir" (fin de journée) ou se déclare "Absent" via le modal de statut.
2
Modal de délégation Un modal s'ouvre : "Souhaitez-vous désigner un administrateur temporaire ?" avec liste de tous les agents.
3
Désignation L'agent choisi obtient immédiatement les droits __admin__ et reçoit une notification.
4
Révocation automatique Dès que l'admin originel revient (statut présent ou "Rebonjour"), les droits temporaires sont révoqués. L'admin temporaire en est notifié.
Donnée FirebaseValeur
appConfig/tempAdminGrant/grantedToClé de l'agent désigné
appConfig/tempAdminGrant/grantedByClé de l'admin absent
appConfig/tempAdminGrant/grantedAtTimestamp de la délégation
Un seul grant actif à la fois. L'admin temporaire conserve son rôle d'origine comme rôle permanent — seul le grant est ajouté par-dessus.

Files d'attente

Configuration des groupes, tickets et écrans d'affichage

🗂️ Groupes de queue

Un groupe de queue réunit plusieurs locaux partageant une même file. Les tickets sont distribués automatiquement vers le premier local disponible du groupe.

PropriétéTypeDescription
namestringLabel affiché dans la vue Direct (ex: "Accueil – Service général")
localIds[]number[]Locaux qui partagent cette file — rotation automatique entre eux
services[]string[]Services associés à ce groupe (optionnel — pour filtrage)
Débordement : si tous les locaux du groupe sont occupés, le ticket entre dans la file de débordement du groupe (wait_{groupId}). La mascotte signale automatiquement l'état de la file.

Données Firebase par jour (queues/YYYY-MM-DD/) :

CléDescription
{localId}Nombre de tickets en attente dans ce local
wait_{groupId}Tickets en overflow (tous locaux occupés)
tick_{groupId}Dernier numéro de ticket émis (ex: 7 → "A07")
tcall_{groupId}Dernier numéro appelé
names_{groupId}/{n}Nom du bénéficiaire pour le ticket n° n (si nominatifs activés)

🏷️ Tickets nominatifs

Activé par le module enableNamedTickets. À l'émission du ticket, l'agent accueil saisit le nom du bénéficiaire. Ce nom s'affiche sur l'écran public au lieu (ou en plus) du numéro.

1
ÉmissionAccueil → Vue Direct → "Émettre ticket" → sélection groupe → saisie nom → numéro généré (ex: A01)
2
Affichage publicMise à jour immédiate sur public.html — numéro + nom ou numéro seul selon config
3
Appel suivantAgent → "Appel suivant" → son + popup → écran public mis à jour avec le ticket appelé
4
ImpressionSi enableTicketPrint actif → bouton imprimer le ticket (PDF A6)

📺 Écrans publics

Vous pouvez configurer plusieurs écrans d'affichage filtrant des locaux différents — utile pour plusieurs TVs dans différents couloirs.

PropriétéDescription
screens/{screenId}/nameNom de l'écran (ex: "TV Couloir Accueil")
screens/{screenId}/localIds[]Locaux affichés sur cet écran

URLs d'accès :

  • Tous les locaux : public.html?org={ORG_ID}
  • Écran filtré : public.html?org={ORG_ID}&screen={screenId}
L'écran public ne nécessite aucune authentification et se rafraîchit en temps réel via Firebase.

🎭 États réactifs (machine à états)

La mascotte analyse le contexte toutes les 30 secondes et adopte l'état de plus haute priorité (0 = absolue, 99 = défaut). Les états contextuels retournent automatiquement à idle après 12 secondes.

PrioritéÉtatDéclencheurAccessoire
0concentratingBouton 🎯 Focus activé — silence complet🌙 moon
1visitorVisite inter-org en cours⭐ stars
2alarmedFile d'attente ≥ 15 tickets💦 sweat
3celebratingRéservation vient d'être créée⭐ stars
4excitedUn agent vient d'arriver (bonjour)✨ sparkles
5stressedFile d'attente entre 9 et 14 tickets💦 sweat
6happyÉquipe complète ou vendredi dès 15h ou décembre💜 hearts / ⭐ stars
7coffeeLundi entre 7h et 10h☕ coffee
8sleepyAvant 7h ou après 17h🌙 moon
9cozyAucune réservation ce jour (après 9h)—
10boredInactivité souris/clavier > 2 min💭 thought
11curiousInactivité 30s à 2 min💭 thought
12wavingSurvol de la mascotte (hover)—
99idleDéfaut — aucune condition active—
Boutons admin uniquement : 🎉 "Inviter mes amis" et 🎭 "Animations" (panneau de test de tous les états) ne sont visibles qu'aux rôles __admin__, __direction__ et __chef_service__.

Intégrations externes

Firebase, météo, iCal, écran public

🔥 Firebase Realtime Database

  • SDK version : 9.23.0 (mode compat)
  • Préfixe : toutes les données sous orgs/{ORG_ID}/
  • Index recommandé : ajouter ".indexOn": ["createdAt"] sur notifications pour éviter l'avertissement console Firebase
  • Règles de sécurité : lecture/écriture authentifiée par orgId — l'isolation entre organisations est assurée par le préfixe de chemin

🌤️ Météo — Open-Meteo

  • API : open-meteo.com — gratuite, sans clé API
  • Prérequis : appConfig/meta/lat + appConfig/meta/lon (Paramètres → Localisation)
  • Module : enableWeather doit être activé
  • Données : température (°C), code météo WMO, vitesse vent, précipitations
  • Cache : rafraîchissement au maximum toutes les heures

📅 Export iCal

  • Module : enableCalendarSync doit être activé
  • Contenu : réservations de l'agent connecté au format VEVENT standard
  • Compatible : Google Calendar, Apple Calendar, Outlook, Thunderbird
  • Utilisation : bouton "📅 iCal" dans la barre de navigation du calendrier

📺 Écran public (public.html)

  • Authentification : aucune — accès totalement libre
  • Rafraîchissement : temps réel via Firebase listeners
  • Affiche : état des locaux (libre/occupé), ticket actuellement appelé, nombre en attente, heure, message du jour public
  • URLs :
    • Tous locaux : public.html?org={ORG_ID}
    • Écran filtré : public.html?org={ORG_ID}&screen={screenId}
  • Recommandation matériel : TV + mini-PC (Raspberry Pi, Chrome Box) en mode kiosk, résolution minimale 1280×720
